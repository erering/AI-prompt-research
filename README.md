# Prompt Style and AI Performance in Competitive Programming

Companion code and data for the paper *How Prompt Style Affects AI Accuracy and Speed in Competitive Programming*.

This repository contains the prompts, AI-generated solutions, grading
scripts, test cases, baseline outputs, and results for a study comparing
nine prompt styles across five competitive programming tasks, measuring
both accuracy and speed, with a comparison against human contestants on
the accuracy tasks.

**Paper:** [link forthcoming]

## Repository structure

- `Automation/`
  - `Generation.ts` — generates prompts and AI solutions for all tasks (GPT-5.5)
  - `Grade_Clique.ts` — grades the Maximum Clique speed task locally
  - `Grade_Partition.ts` — grades the Number Partitioning speed task locally
- `Research/`
  - `Tasks/` — task statements given to the model
  - `Prompts/` — the prompts used, one per prompt style per task (nine per task)
  - `Prompts/Prompt_Strategy_MetaData` — the nine style instructions given to the model when generating prompts
  - `Base_Lines/` — reference solutions for the two speed tasks
  - `Benchmark_Testcases/` — test inputs for the speed tasks, up to the first size the baseline could not solve
  - `Baseline_Outputs/` — the baselines' correct answers for each test case
  - `Runs/` — AI-generated solutions (`AiCode.txt`) and their grades (`Results`), per prompt and iteration

## How it works

Prompts and solutions were generated by `Automation/Generation.ts` using
the OpenAI API with the model ID `gpt-5.5` (the alias, not a pinned
snapshot). Prompts were generated with the reasoning effort set to high. Each prompt was then sent to the solver
nine times, each in a separate API call with no conversation history
(reasoning effort: medium).

Grading followed two paths depending on the task type:

- **Accuracy tasks** (Prisoner Challenge, Message, Migrations — from the
  IOI) were graded by submitting each solution to the
  [oj.uz](https://oj.uz) online judge. There is no grading script for
  these tasks in this repository, since oj.uz performed the grading using
  the official test data and scoring.

- **Speed tasks** (Maximum Clique, Number Partitioning) were graded
  locally by `Grade_Clique.ts` and `Grade_Partition.ts`. Each solution was
  run on test cases of increasing size N under a 1-second limit; the score
  is the largest N solved before the first failure, normalized to a
  task-specific ceiling (N = 220 for Maximum Clique, N = 49 for Number
  Partitioning, the largest cases the baselines solved under a 10-second
  limit). A wrong answer, runtime error, or compilation error scores 0.

## Reproducibility notes

- **Prompts are not regenerable identically.** `Generation.ts` generates
  prompts freshly through the model on each run, so re-running it produces
  *different* prompts. The exact prompts used in the study are the ones
  saved in `Research/Prompts/`.

- **Compilers.** The two speed tasks were compiled with different
  compilers: Maximum Clique with GCC 16.1.0 (`g++-16`), and Number
  Partitioning with Apple Clang 17.0.0 (`g++`), both using
  `-O3 -march=native -std=c++20`. Because of `-march=native`, timings
  depend on the machine the code is compiled and run on.

- **Hardware.** Speed tasks were run locally on a 2022 MacBook Air (M2).
  Solutions were graded one after another in a fixed order (by prompt,
  then iteration), with one test case per value of N.

- **Determinism.** Test cases for the speed tasks are generated
  deterministically from fixed seeds, so every solution was evaluated on
  identical inputs. `Benchmark_Testcases/` contains the inputs up to the
  first size the baseline could not solve; larger cases can be regenerated
  exactly by the grading scripts. `Baseline_Outputs/` contains the
  baselines' answers used as the correctness reference.

- **Re-running the graders.** Both grading scripts regenerate the test
  cases and baseline outputs when run, overwriting the saved copies in
  `Benchmark_Testcases/` and `Baseline_Outputs/`.

- **Untrusted code.** The graders compile and run AI-generated C++ without
  a sandbox. Run them in an isolated environment if you re-grade.

## Running the code

Requirements: Node.js, a C++20 compiler (`g++-16` and/or `g++`), and an
OpenAI API key set as the `OPENAI_API_KEY` environment variable.

Install the dependencies once, from the repository root:

```
npm install
```

Then run each script from the repository root:

```
npx tsx Automation/Generation.ts
npx tsx Automation/Grade_Clique.ts
npx tsx Automation/Grade_Partition.ts
```
